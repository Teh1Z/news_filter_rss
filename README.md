# News Filter: агрегатор RSS с фильтрами по ключевым словам и темам

Web-приложение собирает новости из RSS/Atom-каналов и показывает каждому пользователю
только те, что прошли его фильтры. У каждой новости видно, какой фильтр её пропустил
и по какому техническому критерию: найденные словоформы или z-оценка семантической близости.

Реализовано:
- поиск по ключевым словам (стемминг для русского и английского, фразы, префиксы, обязательные и исключающие термы);
- семантический поиск по темам (локальная модель `BAAI/bge-m3`, работает без интернета и API-ключей);
- несколько пользователей: у каждого свои фильтры и свой список читаемых каналов, можно добавлять новые каналы;
- собственный тестовый RSS-канал, в который можно публиковать посты из интерфейса;
- лента обновляется онлайн через Server-Sent Events.

## Запуск

```bash
cd project_2
./run.sh            # при первом запуске создаёт .venv и ставит зависимости
```

Откройте http://127.0.0.1:8000.

При первом запуске модель `BAAI/bge-m3` (~2,3 ГБ) скачивается с HuggingFace. Дальше она
грузится из локального кэша, и интернет нужен только для чтения RSS. Пока модель загружается
(несколько секунд), фильтры по ключевым словам уже работают, а эмбеддинги новостей досчитываются
после загрузки.

Настройки задаются переменными окружения (см. `app/config.py`):

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `NEWS_PORT` | `8000` | порт |
| `NEWS_POLL_INTERVAL` | `120` | период опроса каналов, с |
| `NEWS_SEMANTIC_THRESHOLD` | `2.0` | порог z для новых тематических фильтров |
| `NEWS_EMBED_MODEL` | `BAAI/bge-m3` | модель эмбеддингов |

Чтобы начать с чистого состояния, удалите папку `data/`.

## Архитектура

```
                ┌─────────────────────── FastAPI (app/main.py) ───────────────────────┐
 Браузер ◄──────┤ REST /api/...   SSE /api/events   статика /   тестовый RSS /rss/test.xml│
 (static/)      └───┬──────────────────────┬──────────────────────────────▲──────────────┘
                    │                      │ события «новые статьи»       │ HTTP, как любой
                    ▼                      │                              │ внешний канал
          filtering.build_feed      fetcher.poll_loop ──── httpx + feedparser ──► внешние RSS
           │            │                 │ дедупликация по guid
           ▼            ▼                 ▼
   keyword_engine  semantic_engine ◄── эмбеддинги новых статей (bge-m3, MPS/CPU)
           │            │                 │
           └──── index (в памяти): токены + векторы ◄── SQLite data/news.db
```

| Модуль | Что делает |
|---|---|
| `app/main.py` | API, тестовый RSS-канал, SSE, запуск фоновых задач |
| `app/db.py` | SQLite: `users`, `feeds`, `subscriptions`, `filters`, `articles`, `local_posts` |
| `app/fetcher.py` | опрос каналов раз в `POLL_INTERVAL`, разбор RSS/Atom, очистка HTML, дедупликация, эмбеддинги |
| `app/index.py` | индекс статей в памяти: токены со стемами и векторы, чтобы не пересчитывать их на каждый запрос |
| `app/text.py` | очистка HTML, токенизация, стемминг Snowball (ru/en) |
| `app/keyword_engine.py` | движок ключевых слов |
| `app/semantic_engine.py` | движок семантики |
| `app/filtering.py` | применяет фильтры пользователя к статьям его каналов и собирает объяснения |
| `app/static/` | интерфейс: HTML + JS без сборки |

Как устроено:
- Каталог каналов общий, подписки у каждого пользователя свои. Статья из канала скачивается
  и векторизуется один раз, сколько бы пользователей её ни читали.
- Фильтры применяются при запросе ленты, а не при сборе новостей. Поэтому новый или
  изменённый фильтр сразу действует на всю накопленную базу. Это быстро: стемы и эмбеддинги
  статей уже посчитаны, семантика сводится к одному матричному умножению.
- Новость попадает в ленту, если её пропустил **хотя бы один** включённый фильтр (OR).
- Онлайн-обновление: после сбора новых статей сервер шлёт событие по SSE, и клиент
  перезапрашивает ленту. Новые карточки на несколько секунд подсвечиваются.

## Движок ключевых слов

Текст статьи (заголовок и описание) разбивается на токены. Каждый токен приводится к нижнему
регистру, `ё` заменяется на `е`, затем берётся стем Snowball: русский для кириллицы, английский
для латиницы. Слова короче 4 букв не стеммятся, иначе «ИИ» превратилось бы в «и». Запрос
разбирается на термы через запятую:

| Запись | Смысл |
|---|---|
| `нейросеть, ИИ` | любой из термов (OR); сравнение по стемам: «нейросети», «нейросетью» тоже совпадут |
| `машинное обучение` | фраза: стемы слов подряд, совпадёт «машинному обучению» |
| `нейро*` | префикс |
| `=Apple` | точная словоформа; аббревиатуры (`NASA`, `ЦБ`) всегда ищутся точно |
| `+Россия` | обязательный терм |
| `-реклама` | исключающий терм |

Правило: новость проходит, если нет исключающих совпадений, найдены все обязательные термы
и хотя бы один обычный терм (если обычные термы есть). В объяснении указано, какой терм
сработал, каким способом (стем, префикс, точная форма, фраза), в каком поле и в какой
словоформе. Найденные слова подсвечиваются в карточке.

## Семантический движок

Модель: `BAAI/bge-m3`, многоязычная, поэтому русская тема находит и английские новости.
Вектор статьи строится по заголовку и описанию.

Сырой косинус между короткой темой («спорт») и статьёй плохо сравним между статьями:
«общие» тексты (погода, курьёзы) похожи сразу на всё. Поэтому оценка калибруется по
**фоновым рубрикам**: для каждой статьи считается похожесть на 40 нейтральных рубрик
(политика, спорт, наука, погода, …), их среднее μ и разброс σ. Итоговая оценка:

```
z = (cos(статья, тема) − μ_статьи) / σ_статьи
```

Она показывает, во сколько σ тема ближе к статье, чем типичная рубрика. Статья проходит
фильтр, если `z ≥ порог` (по умолчанию 2.0; порог можно менять у каждого фильтра прямо в
списке). Тему можно задать несколькими формулировками через запятую (`космос, астрономия`),
тогда берётся лучшая.

Как выбирались параметры (проверено на ~370 реальных новостях Lenta, РИА, Ведомостей, Хабра, BBC, NASA):
- `multilingual-e5-small/base` и `paraphrase-multilingual-*` плохо разделяют темы
  (косинусы почти одинаковые для всех пар); `bge-m3` разделяет заметно лучше;
- калибровка по 40 рубрикам даёт меньше ложных срабатываний, чем по 20, и намного меньше, чем сырой косинус;
- максимум по формулировкам работает лучше, чем их усреднённый вектор (центроид);
- при z ≥ 2 темы «спорт», «экономика», «ИИ», «космос» дают почти чистую выдачу.
  Ограничение: многозначные формулировки (например, «ракеты» или «полёты») тянут военные
  и авиационные новости, поэтому формулировки темы стоит выбирать однозначными.

В объяснении к новости видно косинус, лучшую формулировку, μ, σ, итоговое z и порог.

## Тестовый RSS-канал

Вкладка «Тестовый канал»: заголовок, текст, автор → «Опубликовать». Пост сохраняется в
`local_posts` и сразу отдаётся по адресу http://127.0.0.1:8000/rss/test.xml как обычный
RSS 2.0. Сборщик забирает этот канал по HTTP, тем же кодом, что и внешние каналы.
Если пост подходит под фильтры пользователя, он появляется в ленте через 1–2 секунды.

## Сценарий демонстрации

1. `./run.sh`, открыть http://127.0.0.1:8000. Пользователь `demo` уже настроен:
   фильтр по словам «ИИ» и тема «Космос».
2. Показать ленту. Раскрыть «Почему эта новость здесь» и показать технические критерии.
   Переключатель «Все новости (с причинами)» показывает и отсеянные новости с объяснением,
   почему они не прошли.
3. «Тестовый канал»: опубликовать, например, «Нейросеть помогла астрономам найти экзопланету».
   Пост появится в ленте с двумя бейджами: слова и тема.
4. «Фильтры»: добавить новый фильтр (например, тему `спорт` или слова `ЦБ, ключевая ставка`).
   Лента сразу пересчитается.
5. Новый канал от преподавателя: вкладка «Каналы» → вставить URL → «Добавить канал».
   Статьи загрузятся сразу. Второй вариант: дописать URL в `feeds.txt` и перезапустить сервис.
   Новые URL из файла при старте добавляются в каталог и подписываются всем пользователям.
6. Несколько пользователей: «+ Новый» → у нового пользователя пустой набор фильтров и
   подписки на каналы по умолчанию. Свои фильтры и каналы у разных пользователей не
   пересекаются.

## API (кратко)

Полная схема: http://127.0.0.1:8000/docs

- `GET/POST /api/users`, `DELETE /api/users/{id}`
- `GET/POST /api/users/{id}/feeds`, `PUT /api/users/{id}/feeds/{feed_id}` (подписка), `DELETE /api/feeds/{id}`
- `GET/POST /api/users/{id}/filters`, `PATCH/DELETE /api/filters/{id}`
- `GET /api/users/{id}/feed?all=false`: лента с объяснениями
- `GET/POST /api/test-posts`, `GET /rss/test.xml`
- `GET /api/events` (SSE), `POST /api/refresh`, `GET /api/status`
